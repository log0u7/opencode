# OpenTofu

## When to use

- Running Terraform-style workflows without the HashiCorp Terraform binary.
- executing `tofu` commands (init, plan, apply, destroy) in environments where HashiCorp licensing or provider restrictions apply.
- Multi-hypervisor provisioning when the open-source plugin ecosystem suffices.

## Core principles

- **Binary compatibility**: `tofu` aims to be a drop-in replacement for `terraform` for most commands.
- **Provider parity**: Core providers (aws, azure, google, vsphere, hyperv, kvm) are maintained; proprietary Alibaba/cloudflare providers may lag.
- **State compatibility**: State files generated by Terraform are generally readable, but `backend` configurations may differ.
- **Pin versions**: Lock `tofu` version in CI pipelines; provider versions should follow the same constraints as Terraform.

## Workflow

1. `tofu init` - install required providers.
2. `tofu fmt` - format HCL code.
3. `tofu validate` - validate configuration.
4. `tofu plan -out=plan.out` - generate reviewed plan.
5. `tofu apply plan.out` - apply reviewed plan.

## Anti-patterns

- Assuming `tofu` supports all Terraform Enterprise features (it does not).
- Mixing `terraform` and `tofu` commands on the same state file without migration.
- Committing `.tofu.hcl` or sensitive state without encryption.
